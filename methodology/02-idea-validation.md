# 创意验证与需求测试

## 为什么大部分创意死在这里

> "我有一个好主意" ≠ "有人愿意为它付钱"

最常见的失败模式：
- 做了一个「没人要」的产品
- 用户说"不错"但不用
- 解决的痛点不够痛

## 验证金字塔

```
        ┌─────────┐
        │  付费    │ ← 最强信号：用户真掏钱了
       ┌┴─────────┴┐
       │  参与测试  │ ← 用户愿意花时间试用
      ┌┴───────────┴┐
      │  表达兴趣    │ ← 用户说"我需要这个"
     ┌┴─────────────┴┐
     │  问题存在      │ ← 确认痛点真实存在
    └───────────────┘
```

> 越往上信号越强。停留在"表达兴趣"阶段的验证不可靠。

## 验证方法

### 1. 问题访谈（定性验证）

找 5-10 个目标用户，问这些：

| 问题 | 目的 |
|------|------|
| 上次遇到这个问题是什么时候？ | 确认频率 |
| 你怎么解决的？花了多久？ | 了解现状 |
| 为什么不用 XX（竞品）？ | 找到差距 |
| 如果有工具能帮你自动完成，你愿意付多少钱？ | 测试付费意愿 |
| 如果现在就能用，你第一个想让它做什么？ | 获取功能优先级 |

> ⚠️ 不要问"你觉得这个想法怎么样？"——用户会礼貌地说好。

### 2. Landing Page 测试（定量验证）

做一个简单的落地页，描述产品价值，放一个"加入等待名单"按钮。

| 指标 | 健康值 | 优秀值 |
|------|--------|--------|
| 点击转化率 | > 3% | > 8% |
| 邮箱注册率 | > 5% | > 15% |
| 用户推荐率 | > 2% | > 5% |

工具推荐：Carrd + Google Forms / Tally / Typeform

### 3. 人工模拟 MVP（最省钱的验证）

在产品做出来之前，人工模拟服务来验证需求。

| 场景 | 模拟方式 |
|------|----------|
| AI 分析工具 | 人工分析 + AI 辅助，手动交付结果 |
| 自动化工作流 | 手动执行流程，看用户是否愿意付费 |
| 推荐系统 | 人工筛选推荐，测试用户满意度 |

> 核心原则：**在上游验证，不要在下游验证。** 先确认有人要，再写代码。

### 4. 竞品分析

即使有竞品，不一定是坏事——说明市场存在。关键是：

| 分析维度 | 问题 |
|----------|------|
| 竞品做对了什么 | 用户为什么用他们？ |
| 竞品做错了什么 | 用户抱怨最多的是什么？ |
| 差异化机会 | 我们能做什么竞品做不到的？|
| 专利壁垒 | 竞品有专利保护吗？能绕开吗？|

使用 [`templates/competitive-analysis.md`](../templates/competitive-analysis.md)

## 验证失败怎么办

1. **回到痛点** — 痛点不够痛，换一个
2. **调整方案** — 方案不对，痛点对，换思路
3. **缩小范围** — 做太宽了，找一个垂直细分切入
4. **归档放弃** — 用最小时间成本确认此路不通，也是收获

> 验证失败 ≠ 失败。快速否定错的方向，比坚持做一个对的方向更难也更重要。
